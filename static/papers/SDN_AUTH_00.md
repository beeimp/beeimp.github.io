## 서론

- SDN은 제공하는 이점에서 주요 문제 발생

  - 컨트롤러와 네트워크 어플리케이션 간의 신뢰 문제에서 보안 위협 존재
    - 네트워크 어플리케이션에서 상대방 트래픽 흐름 조작
    - 네트워크 어플리케이션 설계 부실로 네트워크 작동을 손상시키는 보안 취약점

- SDN은 네트워크 어플리케이션의 신뢰 평가를 위한 공식적인 검증 기법이나 의미론이 존재하지 않음 - [6][7]
- 네트워크 애플리케이션이 컨트롤러로 인스턴스화되면 네트워크 상태에 대한 모든 액세스 권한이 자동으로 상속되는 심각한 취약점 존재

  - 프로그램 모듈의 신뢰성과 신뢰성을 검증하는 방법에서 네트워크 어플리케이션의 위협 발생
    - 네트워크 어플리케이션은 플로우 테이블, 장치 구성, CPU Memory, Ran Partition, 입출력 포트 등 중요한 네트워크 리소스에 액세스할 수 있기 때문

- 네트워크 관리자는 컨트롤러 모듈 및 네트워크 어플리케이션의 신뢰성을 검증이 어려움
- 알고 있는 범위 내에서 네트워크 응용프로그램과 컨트롤러의 상호 작용 및 연결을 검증하는 액세스 제어 메커니즘이 없어 악의적인 공격에 노출될 위험 존재 - [14]

  - 중요한 트래픽 리디렉션, 컨트롤러 스푸핑, DoS 공격, 네트워크 정찰 공격, 흐름 규칙 변조 등

- 따라서, 본 논문은 새로운 신뢰 관리 프레임워크를 제공하는데 기여

  - 네트워크 기능 가상화 계층에 있는 다양한 네트워크 어플리케이션을 인증
  - 설정된 네트워크 정책을 준수하도록 권한 부여 및 제한 네트워크 어플리케이션 동작을 적용
  - 네트워크 어플리케이션과 SDN 컨트롤러 간의 SLR(Subjective Logic Reasoning) 기반 신뢰 관계 평가

## 이론적 배경

### Northbound Interface

- 컨트롤러와 네트워크 어플리케이션 간 상호 작용을 위한 인터페이스 - [7]
- 신뢰할 수 있는 네트워크 어플리케이션만이 네트워크에서 서비스를 프로그래밍하고 요청할 수 있도록 허용이 필요 - [16]
- 네트워크 상태를 제어하기 위한 Read, Write, 알림 수신, 시스템 호출 기능을 제공하는 액세스 권한에 의해 구현 가능 - [17]

### Network Application

- 서비스 API 호출 및 이벤트 콜백을 통해 공유 SDN Control Plane 상태와 상호 작용함
- 특정 서비스 및 서비스 메소드를 통해 컨트롤러 모듈(ex: 네트워크 정보 베이스)에 접근할 수 있음
- 이벤트 콜벡의 경우 컨트롤러에 등록하고 관심 이벤트를 Subscribe 할 수 있음
- 기본적으로 상호 작용은 네트워크 상태 읽기, 네트워크 정책 쓰기, 이벤트 알림 받기 및 시스템 호출을 통한 리소스 액세스와 관련된 제어를 말함

### 네트워크 상태 읽기

- REST API 또는 Native Controller API를 통해 컨트롤러와 네트워크 어플리케이션 간 통신 - [8] (ex: ODL, Floodlight)
- OpenFlow - 컨트롤러가 네트워크 어플리케이션의 요청을 데이터 영역의 포워딩 장치에 전달하는 매개자 역할 - [19]
- Data Plane의 Forwarding Deivce - 컨트롤러가 해석한 요청된 데이터를 응답하고, HTTP 응답 형식으로 네트워크 어플리케이션에 다시 전달 (REST API를 사용하는 경우)
  - Native Controller API의 경우 쿼리를 통해 유사한 방법을 따름

### 네트워크 정책 작성

- 네트워크 상태 변경을 구현하거나 적용하기 위해 네트워크 어플리케이션에서 컨트롤러에 HTTP POST Request를 전송
  - 프록시로 사용되는 컨트롤러의 경우 - Northbound API를 통해 Data Plane에 관련 스위치의 플로우 테이블에서 구현될 플로우 수정 또는 패킷 출력 명령으로 변환 - [20]
  - HTTP POST 메소드에 의해 구현된 경우 - 쓰기 액세스 권한에 의해 활성화 - [21]
    - 쓰기 액세스 권한 - 흐름 규칙 추가, 흐름 규칙 수정, 지정된 포트로 흐름 전송, VLAN 태그 할당, 흐름 대기열 할당, 흐름 미터링 및 삭제 등
- 네트워크 전역 상태를 위한 네트워크 정책 작성은 네트워크 어플리케이션에 네트워크 제어 및 관리 측면에서 우위를 제공
  - but, 보안 및 올바른 네트워크 작업을 위해 필요한 액세스 권한에 대한 정확한 이해 필요 - [22]

### 알림

- 스위치 가입 또는 탈퇴 이벤트, 스위치 포트 상태(상향 또는 중단 상태), 링크 상태 등이 포함

### System Call

- 네트워크 어플리케이션은 로컬 운영 체제 리소스에 액세스 가능하여 로컬 시스템의 모든 어플리케이션에 공유됨
  - 공유 리소스 - CPU, RAM, 스토리지, 프로세서 스레드, 파일 시스템 및 커널 라이브러리
- 컨트롤러는 운영 체제에서 제공하는 추상화를 기반으로 하기 때문에 운영 체제 리소스에 대한 액세스 모니터링 필요

#### 네트워크 어플리케이션과 컨트롤러의 상호 작용 방식 분석을 통한 취약성 식별

- 네트워크 어플리케이션의 신뢰성 확인 방법이 존재하지 않음 - [16], [21]
  - 네트워크 요청을 보내기 전 ID나 자격 증명을 확인하지 않음
- 네트워크 어플리케이션에 의해 실행 중인 요청 또는 작업 집합을 모니터링, 제한, 허용치 지정에 대한 메소드 없음 - [4], [23]

#### 식별한 취약점에 대한 잠재적 해결책

- 네트워크 어플리케이션 식별
- 네트워크 상태 관리에 네트워크 어플리케이션이 가지는 액세스 레벨 제어
- 컨트롤러와 네트워크 어플리케이션 간 신뢰할 수 있는 통신 제공

## 연구 방법

- 논의된 보안 문제를 고려하여 관리 프레임워크를 설계하고, 모듈을 개발함

- 신뢰 관리 프레임워크의 시스템 설계는 컨트롤러와 네트워크 어플리케이션 간의 위협 완화를 위한 보안 요구사항 정의

  - 자격 증명을 통해 네트워크 어플리케이션 식별 방법 제공

  - 네트워크 어플리케이션에 대한 권한 집합 정의

  - 컨트롤러와 네트워크 어플리케이션 간의 상호 작용을 기반으로 신뢰성과 의존성 평가

- 신뢰 관계 구축을 위한 프레임워크에서 세 가지 주요 블록 구성

  - 인증 모듈

  - 승인 모듈

  - 신뢰 평가 모듈

## 결과

- 제안된 신뢰 프레임워크에서는 Network Function Virtualization 계층에 위치한 네트워크 애플리케이션의 신뢰성을 검증하고 성공적으로 인증된 애플리케이션에 대한 각 권한 권한을 할당하는 방법을 소개
